# Relay for Android and iOS

Expo Router / TypeScript client for the adjacent Laravel private chat application. It uses the existing `/api/v1` API, Sanctum bearer tokens, authorized Pusher channels and Laravel-issued temporary Cloudflare TURN credentials. The backend and web client share the same account-management contract.

## Choose a backend

Run `npm start` to start Android automatically with local Laravel, or `npm run start:dev` for `https://chat.roshanlama.com.np`. Expo boots an available emulator and opens your installed development build; it reuses an already connected device. The backend address is selected automatically; no .env editing is needed between runs. Use `npm run start:server` for Metro only or `npm run start:ios` for the local iOS simulator. Hosted development, staging and production currently share the supplied server and its data.

See [environment commands and build profiles](docs/environments.md) for optional overrides, Pusher variables and EAS setup.

## Run a development build

Use Node 22+, the installed SDK 58 lockfile, and an Android SDK/JDK 21 for local Android builds. Local iOS compilation requires macOS/Xcode. EAS can compile both platforms remotely. Expo Go cannot load the Pusher, WebRTC or call-audio native modules.

```powershell
Set-Location C:\Users\roslm\OneDrive\Documents\chat-app-native
npm ci
# Optional: set shared public Pusher values once; preserve an existing .env.
if (!(Test-Path .env)) { Copy-Item .env.example .env }
npm run android
# On macOS instead:
npm run ios
# Subsequent starts after the development client is installed:
npm start
```

For remote development builds:

```powershell
npx eas-cli@latest login
npx eas-cli@latest build:configure
npx eas-cli@latest build --profile development --platform android
npx eas-cli@latest build --profile development --platform ios
npm run start:dev
```

Install the resulting development client on the device. Set your own unique bundle/package identifiers in `app.json` before distribution, and supply EAS signing/project configuration when prompted. Rebuild the native client after adding or changing native modules, permissions, scheme or plugins. `eas.json` also contains preview and production profiles. Run `npx eas-cli@latest build --profile production --platform all` only after completing device acceptance testing and production configuration.

Native projects are generated by Expo; do not hand-edit `android/` or `ios/`. The configured plugins cover Router, splash screen, SecureStore, Sharing, Audio, Video, ImagePicker, local Notifications and WebRTC, plus optional-camera and Windows CMake plugins. Microphone and optional camera purpose strings are included. Audio background playback/recording is disabled. React Compiler is disabled; lifecycle controllers use explicit effects and refs. ESLint's effect-state initialization rule is disabled for those external lifecycle boundaries; other hook checks remain enabled.

On Windows, the CMake config plugin keeps generated native build files in a short cache on the checkout's drive (for example `C:\.relay-cxx`) and requests hashed object paths. This avoids Ninja's 260-character path limit even in this OneDrive checkout. Cache folders are isolated by checkout and module. You can set `RELAY_CMAKE_BUILD_ROOT` to another short writable absolute path if needed. After changing native config plugins, regenerate with `node scripts/expo-environment.mjs local prebuild --platform android --no-install`. Do not hand-edit generated CMake files. The in-place Android build and emulator installation have been verified with this fix.

## Public configuration and backend

`.env.example` contains only:

```dotenv
EXPO_PUBLIC_API_ORIGIN=
EXPO_PUBLIC_PUSHER_KEY=
EXPO_PUBLIC_PUSHER_CLUSTER=
```

The origin is the Laravel origin, without `/api/v1`. A public Pusher key is not its app secret. Never add a bearer token, Pusher app secret, permanent Cloudflare key/token or production account password to Expo configuration. Expo public values are bundled into the application. Tokens are stored in iOS Keychain / Android Keystore-backed Expo SecureStore with device-only, unlocked accessibility, and are never stored in AsyncStorage. Temporary ICE credentials remain in memory.

Use HTTPS for deployment and physical-device testing; devices must trust the certificate. Configure the Laravel application URL, queue worker, scheduler, mail, Pusher and backend-only Cloudflare TURN settings using the backend README and `docs/cloudflare-turn.md`. No new database or alternate auth service is required. Calls are disabled when the public Pusher configuration is absent. Messaging remains usable through REST and foreground reconciliation.

Local API addressing:

| Device | Development API origin |
| --- | --- |
| Android Studio emulator / USB-debugging device | `http://localhost:8000` through automatic ADB reverse forwarding in local npm commands |
| iOS simulator on a Mac | `http://localhost:8000` reaches that Mac |
| Physical Android/iOS device | Reachable LAN hostname/IP or an HTTPS development tunnel |

The local npm commands forward Android's backend port through ADB so the app can use localhost. Physical iPhones and Wi-Fi-only phones need a reachable LAN address or HTTPS tunnel. For LAN testing, start Laravel with `php artisan serve --host=0.0.0.0 --port=8000`, allow the development port through the local firewall and use the computer's reachable LAN address. Keep development-only HTTP exceptions out of your production deployment. Do not point an HTTPS application at a backend with an untrusted/self-signed certificate.

The backend's local admin seeder provides `admin@example.com` / `password` only under `APP_ENV=local` with blank seed credentials. From the backend repository, use `php artisan db:seed --class=AdminSeeder` if local test provisioning is needed. Do not seed or use that account in production. Existing accounts are not overwritten by the seeder.

## Implemented flows

- Invite-only token login, validated secure session restore, revoked/expired/inactive-account handling, profile/avatar updates and server-confirmed current-token logout. Offline restore keeps the secure token and offers an explicit retry; offline logout remains signed in until revocation succeeds.
- Conversation and active-user discovery with pagination; native, virtualized message history; loaded-history text/filename search; cursor pagination; text and multiple arbitrary file types; UUID-preserving failed-message retries; API/sender-echo deduplication; read states, unread counts, typing throttled to one request per six seconds, approximate presence/last seen.
- Authorized private user/conversation and presence Pusher subscriptions. Reconnect, network return and foreground wake validate the session and reconcile messages through all `after_id` cursor pages plus conversations, notifications and active calls. Foreground REST reconciliation also runs every 30 seconds. Failed subscriptions are released and retried. Logout/account changes clear subscriptions, SDK listeners, in-memory messages, pending-upload references and private downloads.
- Document and photo/video selection, upload progress/cancellation, staged attachment reuse on message retry, private authenticated downloads, image/video/audio previews and native sharing. Every file has a download/share action. Media is first downloaded into the app-private cache; no token is placed in a URL. Sharing exports only when explicitly requested. Server MIME and storage policies remain authoritative.
- Audio/video call controls, incoming acceptance/rejection, outgoing cancellation, server statuses, duration, mute/camera/speaker routing, chunked SDP/ICE assembly, early ICE buffering, fresh authenticated ICE issuance, and 20-second participant heartbeats. Microphone acquisition is independent and mandatory. Camera acquisition failure continues with audio and a receive-only video transceiver.
- Hang-up immediately closes the peer and stops tracks, disables repeated submissions, shows an ending state, and closes after server confirmation. Failure offers Retry hang-up while capture stays off. Call IDs and generations reject late signals, media acquisitions, heartbeats and broadcasts. Restored accepted calls are ended rather than pretending their old peer can be resumed.
- Notification center, per-notice read state, persisted sound mute and Test sound. Live alerts deduplicate and suppress sounds for the focused conversation, history reconciliation, background activity and active call audio. On Android the foreground chime uses a local notification channel with DND bypass disabled; Test sound requests notification permission if needed. On iOS it honors the silent switch. This does not register a push token or enable background delivery.
- Admin role-gated metrics, searchable/paginated accounts, invitations/resends, name/email/role editing, suspension/reactivation, password reset emails and paginated audit history. Pending members must accept invitations. Backend last-admin and private-content authorization protections remain unchanged.

The client applies the documented default file limits (five attachments, 25 MiB each), 4,000-character messages and 2 MiB avatars. Backend validation still enforces the actual deployment quotas, including total storage. If you intentionally increase server attachment defaults, update the corresponding native preflight checks. Upload cancellation can leave server-staged orphan files for the backend's scheduled cleanup. Failed sends and selected-file retry metadata are retained in memory across navigation; process termination clears this outbox. This is not a durable offline message queue.

Large media is downloaded before local playback. Unsupported codecs and corrupt files may fail preview; download/share remains available. App-private cache files are removed at logout and account changes, and the OS may evict cache files. Load the file again if it has been evicted. Search covers loaded conversations/latest messages and loaded message history; the backend does not expose a global full-text search endpoint.

## Invitation and reset links

The registered native scheme is `chatappnative`. Supported links include:

```text
chatappnative://invitations/123?token=SINGLE_USE_INVITATION_SECRET
chatappnative://reset-password/RESET_TOKEN?email=member%40example.com
```

`+native-intent` normalizes these paths and equivalent HTTPS paths to the account form, which uses the existing invitation/reset APIs. The secret remains in the deep-link payload; it is never an API bearer token. Links are not logged. Accepting an invitation does not bypass pending/suspended-account rules or create a public registration flow.

The existing backend emails still contain website HTTPS links. To make those links launch this app directly, configure your production domain's Apple association file and Android asset links, iOS `associatedDomains`, Android verified intent filters, correct application IDs and signing fingerprints. Those domain/signing assets cannot be provisioned from this checkout. Until then, open the HTTPS email flow on the existing website or deliver the equivalent native-scheme link. Avoid placing reset/invitation secrets in analytics.

## Platform and service boundaries

There is no FCM/APNs delivery, CallKit, Android Telecom/ConnectionService or terminated-app incoming-call support. The backend device endpoint is a future push contract only. No push token is registered by this app. Incoming-call controls are for an open, foreground app. Backgrounding ends capture/calls; returning to the foreground reconciles API state. Audio-focus loss, noisy/disconnected wired routes and ended microphone tracks terminate capture; video-track loss disables camera controls. Network changes show recovery state and retain the backend participant lease; a lost lease/failed peer ends the call and requires redial. OS audio routing always has final control; Bluetooth/route behavior needs physical-device testing.

Installed Pusher React Native SDK 1.3.5 exposes channel authorization but **does not expose Pusher user sign-in/authentication** in its public JS/native bridge. This client does not invent or claim that feature. Backend suspension rejects subsequent bearer/API/channel requests, and session reconciliation removes the local session, but immediate server-driven socket termination cannot be guaranteed for this SDK. A maintained SDK release or a tested native bridge extension for Pusher authenticated users is required for that guarantee. Pusher permissions are never broadened to compensate.

The installed WebRTC 155.0.1 package accepts the installed React Native version; its Expo config plugin 15.0.2 resolves successfully under SDK 58. The plugin's published compatibility table currently stops at SDK 56, so Android/iOS native build and physical-device acceptance remain necessary before distribution. Type checks and bundle generation alone do not certify native runtime compatibility. This client does not refresh TURN credentials mid-call; calls exceeding the issued credential TTL require a separately tested ICE-refresh strategy.

Use the existing React website for browser access. This native client does not provide a WebRTC/Pusher browser shim and is not a replacement website.

## Verification

```powershell
npm test
npm run test:connectivity
npm run lint
npm run types:check
npx expo install --check
npx expo config --type introspect
npx expo export --platform android --platform ios
```

Tests exercise secure-session lifecycle and races, inactive accounts, token expiry, stale-account transport responses, bearer origin restrictions, request cancellation, message/notification deduplication, paginated missed-message recovery, deep-link parsing, out-of-order UTF-8 signal assembly, early ICE, microphone requirements, camera fallback and capture cancellation. Tests use fakes for devices and signaling. See `docs/verification.md` for actual outcomes and remaining acceptance checks.

An optional real-backend contract smoke test creates and revokes one token, reads only authorized resources and never creates messages/calls/users/files:

```powershell
$env:RELAY_API_ORIGIN = 'http://127.0.0.1:8000'
$env:RELAY_TEST_EMAIL = 'your-local-test-account@example.com'
$env:RELAY_TEST_PASSWORD = 'your-local-test-password'
node --experimental-strip-types scripts/api-smoke.mjs
Remove-Item Env:RELAY_TEST_PASSWORD
```

Before release, test web-to-native and native-to-native text/files/read/typing recovery, suspension, protected-file access from a third account, invitation/reset email links, native permission denial, camera-less audio fallback, simultaneous hang-up and cancellation during permissions. Then test real two-way audio/video between physical devices on different networks. Temporarily force relay-only ICE in a diagnostic build to confirm a Cloudflare relay candidate pair, and remove that override afterward. Test device sound/silent settings, audio interruption, Bluetooth/wired routing and app backgrounding. No actual audio/video or live Pusher delivery is certified by mocked tests.

Reference APIs: [Expo SDK 58](https://docs.expo.dev/versions/v58.0.0/), [SecureStore](https://docs.expo.dev/versions/v58.0.0/sdk/securestore/), [FileSystem](https://docs.expo.dev/versions/v58.0.0/sdk/filesystem/), [DocumentPicker](https://docs.expo.dev/versions/v58.0.0/sdk/document-picker/), [ImagePicker](https://docs.expo.dev/versions/v58.0.0/sdk/imagepicker/), [Audio](https://docs.expo.dev/versions/v58.0.0/sdk/audio/), [Video](https://docs.expo.dev/versions/v58.0.0/sdk/video/), [Pusher native SDK](https://github.com/pusher/pusher-websocket-react-native), [React Native WebRTC](https://github.com/react-native-webrtc/react-native-webrtc), [AppState](https://reactnative.dev/docs/appstate).

Chat attachments have separate Download and Share actions. Download opens Android Save as (or the iOS folder picker); Share opens the native share sheet. Rebuild the development client after installing dependencies. `npm install` applies the SDK 58.0.3 intent-launcher patch in `patches/`, which corrects the Android activity result URI.

Outgoing calls play the system ringback sound through the existing InCallManager audio route. Ringback stops on acceptance, cancellation, rejection, failure, timeout or cleanup. The timer starts when WebRTC reports a media/ICE connection, uses local elapsed time to avoid device/server clock differences, and freezes on hang-up. Connection state is also checked each second in case an event was missed. The UI shows Connecting audio until media connects and ends unsuccessful setup after 30 seconds. Remote tracks are aggregated so a streamless video track cannot replace audio. Check two-way audio, ringback volume, speaker/headset routing and the timer on physical devices; automated tests do not verify audible output.

Outgoing ICE candidates wait until the offer/answer is published, then upload sequentially. A transient candidate fetch failure is retried once; a failed route does not terminate the other routes. Healthy, unknown and repeated network callbacks do not produce warnings, and connectivity notices clear on recovery. Fetch errors identify the chat API origin separately from account/session errors. Local Android requires the backend and the npm launcher’s ADB forwarding to remain running.


Administration creates active accounts directly with a confirmed password of at least 8 characters. Edit account supports an optional new password and permanent deletion requires the account email plus a confirmation dialog. Deletion removes shared history/files for both participants. Profile includes Change password with current-password verification. The current device stays signed in for a self-service change; admin-assigned passwords revoke the target’s sessions/tokens.

The chat list starts at the newest messages, follows new messages while near the bottom, and loads older cursor pages automatically when scrolling upward. Reading older messages preserves the visible position.


Incoming calls now start the system ringtone and vibration while Relay is active, and stop the ringtone before media setup or any terminal cleanup. Outgoing calls use system ringback. Android message/missed-call alerts use the system notification sound through the v2 foreground-message channel, avoiding reliance on a quiet/missing custom native resource. iOS uses the bundled chime normalized to 90% peak at player volume 1. Open Notifications → Test sound once to grant Android permission. Raise device ringtone/notification volume as needed; silent mode and Do Not Disturb remain controlled by the OS. These changes use existing modules and apply after reloading the development bundle; actual ringing/speaker levels still need physical-device verification.
